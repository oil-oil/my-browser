$ my-browser ensure
$ my-browser doctor
$ my-browser open "https://example.com/upload"
$ my-browser snapshot <tabId> -n 30
$ my-browser fill @e7 "A quiet local browser tool"
$ my-browser upload @e12 ./video.mp4
$ my-browser fields <tabId> title="#title" upload=".file-row"
$ my-browser screenshot <tabId> --annotate /tmp/page.png
$ my-browser detach

Built for a different kind of browser automation.

Agent Browser and Browser MCP are useful, but My Browser optimizes for one specific promise: let agents operate the user’s real local Chrome with less setup, less context noise, and fewer interruptions.

My Browser

Best when the task needs the user’s current Chrome, real login state, background tab groups, uploads, diagnostics, and a skill that tells agents how to recover.

  • Uses existing local Chrome and its login state.
  • Creates a dedicated automation group by default.
  • Returns compact snapshots, fields, requests, and errors.
  • Skill teaches setup, recovery, safe confirmations, and fallback rules.

Agent Browser

Excellent agent protocol inspiration: daemon sessions, refs, screenshots, waits, and a clear command model. It usually shines for dev verification and controlled browser sessions.

  • Strong CLI vocabulary for web testing and dev server checks.
  • Great ref lifecycle and screenshot workflows.
  • Often works in an automation browser or managed session.
  • Less focused on the user’s already-open Chrome profile.

Browser MCP

Helpful for general browser control inside MCP clients. My Browser adds a local product layer for this workflow: skill-first guidance, Chrome extension bridge, and background group defaults.

  • Good for basic navigation, screenshots, and inspection.
  • Depends heavily on the MCP host and browser connection state.
  • Has fewer opinionated recovery paths for local extension setup.
  • Can require more manual agent reasoning around page state.

Designed around trust, focus, and small outputs.

The CLI behaves like a careful local collaborator: it handles repetitive browser work, explains blocked states, and asks before risky actions.

Background by default

Automation tabs stay grouped and inactive, so users can keep typing, reading, or meeting while the agent works.

Clear recovery

When the extension is offline, the CLI reports the exact missing piece and avoids pretending it already fixed Chrome permissions.

Compact observations

Agents receive the fields, refs, and diagnostics they need without pulling entire pages into the conversation.

Human confirmation

Publishing, deleting, submitting, and other high-risk actions pause behind an explicit confirmation flow.
